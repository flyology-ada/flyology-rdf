Read, write and compare RDF.

Feed a parser what arrives and handle statements as they close, build them by hand under a type system that rules out the invalid ones, and decide whether two graphs say the same thing.

Add the crate

Notation3 and SPARQL are separate dependencies, flyology_n3 and flyology_sparql. The library has no runtime dependency and no tasking; its only concession to a scheduler is an optional cooperative-yield callback.

Read a document

A sink receives one event per statement as the parser reads it. Nothing is retained that the sink does not retain, which is what lets a document larger than memory be read.

Four syntaxes share one parser, chosen at Create: Turtle_Syntax, TriG_Syntax, NTriples_Syntax and NQuads_Syntax.

Input that arrives in pieces

The split may fall anywhere, including inside an escape or a literal, and what comes out does not depend on where it fell.

Notation3 and SPARQL take chunks too. They emit nothing as they read, because a formula and a query are terms and a term means nothing until it is closed; what chunking buys there is the scanner, which is where a split hurts.

Build statements

A predicate is typed as an IRI rather than a term, so a literal in predicate position is a compile error rather than a runtime check.

Compare two graphs

Two documents that differ only in their blank node labels denote the same thing, and comparing their text will not tell you so. Canonicalization decides it: every blank node is labelled from its position in the graph rather than from what it was called.

!

The algorithm has a documented adversarial case: telling apart blank nodes that look alike from every direction requires trying permutations, and a dataset can be built to make that combinatorial. Canonicalization therefore takes a work bound and reports reaching it as a result rather than running until something else gives out.

RDFC-1.0 names SHA-256 and admits SHA-384. The digest is part of the request rather than a setting, because the identifiers a processor issues differ between them.

Notation3

N3 says things RDF cannot. A formula is a term, so a rule is an ordinary statement whose subject and object are graphs.

SPARQL

Queries are read and written back as documents. There is no evaluation: a query here is something to check, format or inspect.

Coverage is the query language: the four query forms, the pattern and expression grammars, property paths, subqueries, VALUES, EXISTS, dataset clauses, aggregates and the RDF 1.2 term syntax. Deliberately absent: SPARQL Update, and evaluation of any kind.

When a document is malformed

Failures are typed. A diagnostic carries a code, the grammar production that failed, and a full source span with byte, line and column at both ends — not a message string to match on.

Flyology RDF is experimental. Interfaces, diagnostics and the binary term format may change before v0.1.0.

Read, write and compare RDF.

Feed a parser what arrives and handle statements as they close, build them by hand under a type system that rules out the invalid ones, and decide whether two graphs say the same thing.

Add the crates

Three crates, taken separately. flyology_rdf stands alone; the other two depend on it for terms and for the shared scanner.

The library has no runtime dependency and no tasking. Its only concession to a scheduler is an optional cooperative-yield callback, so it runs the same in a plain sequential program and inside a lightweight-task runtime.

How it fits together

Four stages, and only the middle two are yours to think about.

One scanner
Token boundaries are decided in exactly one place for all three grammars, with a dialect switch. Deciding them twice is what produces a family of conformance bugs: a scanner that recognises PREFIX by looking ahead misreads a prefixed name whose prefix is prefix.
A parser you feed
The parser holds at most one partial token plus the statement it is assembling. It does not hold the document, and it does not hold what it has already given you.
A sink you write
Events arrive as they complete: a graph declaration, a statement, a diagnostic. What happens to them is entirely your decision — collect, stream onward, or count and discard.
Terms as a flat vector
A term is one allocation: nodes in child-before-parent order with every reference an index. No cycle is representable, and traversing a nested triple term is iterative and bounded rather than recursive.

Read a document

Implement Event_Sink. Only On_Quad usually matters; the other two have null defaults you can leave alone.

Then create a parser, feed it, and finish it. Finish is what tells you whether the document was well formed; it is not optional.

!

If a sink callback raises, the exception propagates unchanged and the parser is poisoned: no later Feed emits anything and Finish reports failure. A sink that fails cannot be half-applied.

The four RDF syntaxes

One parser reads all four. The grammar is chosen at Create and cannot change mid-document, because the syntax decides what a token even is.

Turtle_Syntax
Prefixes, collections, property lists, the RDF 1.2 term syntax. One graph: a graph block is a syntax error.
TriG_Syntax
Turtle plus named graph blocks. This is the default, because it is the syntax that can express everything a dataset holds.
NTriples_Syntax
One statement per line, no prefixes, no abbreviation. Nothing is retained between lines, so a stream of them costs nothing to read.
NQuads_Syntax
N-Triples with a fourth position for the graph name.
i

A base IRI is required for relative references and rejected unless it is absolute. Resolution is strict RFC 3986: a reference carrying its own scheme keeps it, and dot segments are removed whether or not it does.

Named graphs

Every event carries its graph, so a sink never has to remember which block it is inside.

On_Graph_Declaration fires when a block names a graph, which is what you want if you are mirroring the document's structure rather than its content.

Input that arrives in pieces

Call Feed as often as you like. A split may fall anywhere — inside an escape, inside a literal, between the two bytes of a UTF-8 sequence — and what comes out does not depend on where it fell.

Every document in the test suite is parsed twice, whole and one byte at a time, and the two must agree: 1,050 RDF documents, 1,161 N3 documents and 317 SPARQL queries. Notation3 and SPARQL take chunks too, though they emit nothing as they read — a formula and a query are terms, and a term means nothing until it is closed.

Diagnostics

A failure is a value, not a message to match on. It carries what went wrong, which production was being read, and where it was.

The span is given at both ends, in bytes as well as lines and columns, so a caller can underline the offending region without rescanning the input.

Limits and cooperative work

Every bound is declared and none of them is a guess. Reaching one is a diagnostic like any other, not an exception and not a crash.

Long inputs can hand control back. Pass a Work_Checkpoint and the parser calls it every Work_Checkpoint_Interval units of work, which is how a lightweight task yields without the library knowing anything about the scheduler.

i

Maximum_Pending_Bytes is the honest answer to "how much does this actually hold?" — it is the high-water mark of the buffer, which for well-formed input is one partial token.

Terms

Constructors enforce every rule, so an invalid term cannot be built. A predicate is typed as an IRI rather than a term, which makes a literal in predicate position a compile error rather than a runtime check.

RDF 1.2 triple terms nest, and nesting is bounded: Terms.Depth and Terms.Node_Count report what a term costs, and the constructors refuse anything past the model's limits.

Datasets

A dataset is a set, not a list: inserting the same statement twice leaves one. Iteration is deterministic, so two runs over the same data visit it in the same order.

Write

To_TriG writes named graphs as blocks; To_Turtle raises if the dataset holds one, because Turtle cannot say it. For a line at a time there is NQuads_Writers.Write_Quad, which is what canonical output and dataset comparison are built on.

i

A prefixed name is written only when it reads back as one. Anything the grammar would not accept is written as a full IRI instead, which is always legal.

Compare two graphs

Two documents that differ only in their blank node labels denote the same thing, and comparing their text will not tell you so. Canonicalization decides it: every blank node is labelled from its position in the graph rather than from what it was called.

The identifier map is available when you need to say which node in the output was which node in the input, and the digest is part of the request because RDFC-1.0 admits two and the labels differ between them.

!

The algorithm has a documented adversarial case: telling apart blank nodes that look alike from every direction requires trying permutations, and a dataset can be built to make that combinatorial. Canonicalization therefore takes a work bound and reports Work_Limit_Reached rather than running until something else gives out.

The binary encoding

A compact, self-delimiting encoding for a term or a statement, for when you are putting one in a cache or on a wire rather than in a document.

!

The binary format is explicitly unstable and stays that way after v0.1.0. Encode into a cache you can rebuild, not into storage you must migrate.

Notation3

N3 says things RDF cannot. A formula is a term, so a rule is an ordinary statement whose subject and object happen to be graphs.

The result is the document as a formula, so reading it is the same walk at every level.

SPARQL

Queries are read and written back as documents. There is no evaluation: a query here is something to check, format or inspect.

The tree is the same flat vector the RDF terms use, so walking it is index arithmetic rather than pointer chasing.

Coverage is the query language: the four query forms, the pattern and expression grammars, property paths, subqueries, VALUES, EXISTS, dataset clauses, aggregates and the RDF 1.2 term syntax. The parser also rejects what the grammar alone admits — a projection that repeats a name, an AS that takes a name already in scope, a variable projected past a GROUP BY that dropped it. Deliberately absent: SPARQL Update, and evaluation of any kind.

Flyology RDF is experimental. Interfaces, diagnostics and the binary term format may change before v0.1.0.
